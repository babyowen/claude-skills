# Slide Craft - 演示文稿生成器

将 Markdown 或纯文本大纲转换为精美的 HTML（带动画）和 PowerPoint 演示文稿。

## 概述

此技能将结构化的文本内容转换为功能完整的 HTML 和 PPTX 演示文稿。系统智能分析内容类型，自动选择最合适的模板，确保专业性和视觉效果。

### 核心特性

- **多格式输入**: 支持 Markdown 和纯文本格式
- **智能模板匹配**: AI 自动识别内容类型并选择合适的展示模板
- **双输出格式**: HTML（在线展示，带 GSAP 动画）和 PPTX（离线编辑）
- **6 种核心布局模板**: 封面页、左右分栏、三栏并列、中心辐射、横向流程、数据总结
- **固定封面设计**: 遵循公司模板规范，保持品牌一致性
- **中信配色方案**: 使用标准的企业配色
- **混合生成策略**: 优先匹配模板，特殊内容基于设计系统自由生成

## 输入格式

### Markdown 格式（推荐）

Markdown 是推荐的输入格式，易于编写和维护。

```markdown
# 演示文稿标题
副标题或部门名称
2025年2月

## 第一页标题

- 要点 1
- 要点 2
- 要点 3

## 第二页标题

1. 步骤 1 - 描述
2. 步骤 2 - 描述
3. 步骤 3 - 描述

---

> 重要引用或宣言

## 团队介绍

- **姓名** - 职位, 简介
- **姓名** - 职位, 简介
```

**Markdown 语法支持**:
- `# 标题` - 主标题（封面页）
- `## 标题` - 内容页标题
- `- 要点` 或 `* 要点` - 无序列表
- `1. 要点` - 有序列表
- `![alt](url)` - 图片
- `> 引用` - 引用文本
- `---` - 幻灯片分隔符

### 纯文本格式

简单的文本格式，通过模式识别自动解析。

```
演示文稿标题

第一页标题
- 要点 1
- 要点 2

第二页标题
1. 步骤 1
2. 步骤 2
```

## 工作流程

系统采用**混合策略**：优先匹配6种核心模板，特殊内容基于设计系统自由生成。

### 核心布局模板（6种）

| 模板名称 | 布局特征 | 适用场景 | 识别关键词/模式 |
|---------|---------|---------|----------------|
| **封面页** | 居中大标题+背景图 | PPT开头 | `# 标题` + 副标题 + 日期 |
| **左右分栏页** | 左图右文/左文右图 | 项目介绍、对比 | 背景介绍 + 多模块内容 |
| **三栏并列页** | 三个等宽模块 | 多维度展示 | 3个并列主题 + 各自要点 |
| **中心辐射页** | 圆形核心+辐射分支 | 核心能力、工作重点 | 中心主题 + 5-6个子项 |
| **横向流程页** | 4-6阶段横向排列 | 项目进展、工作流程 | 步骤、阶段、1. 2. 3. |
| **数据总结页** | 卡片+底部大数据 | 成果汇报 | 内容卡片 + 关键数据 |

### 匹配策略

**Step 1: 内容分析**
- 识别内容结构（总-分/并列/递进）
- 统计信息密度（模块数量、要点数量）
- 判断内容类型（介绍/对比/流程/数据）

**Step 2: 模板匹配**
- 优先匹配6种核心模板（覆盖率80%）
- 内容超长时自动拆分多页
- 特殊内容标记为"自由生成"

**Step 3: 自由生成（特殊情况）**
- 基于设计系统（`references/design-system.md`）
- 使用通用组件（色块标题栏、内容卡片、数据指标块、流程箭头）
- 严格遵循中信配色和字体规范

### 设计系统

所有布局和自由生成都遵循 `references/design-system.md` 中定义的：
- 颜色系统（中信标准配色）
- 字体系统（中英文字体规范）
- 字号层级（H1-H3, Body, Data, Caption）
- 间距系统（页面边距、模块间距、行间距）
- 布局网格（左右分栏、三栏并列、页面高度分配）
- 通用组件（4种标准化组件）
- 视觉层次规则（对比、对齐、留白）

## 工作流程

### 步骤 1: 准备内容

创建 Markdown 文件（例如 `presentation.md`）：

```markdown
# 产品介绍
打造下一代用户体验
2025年2月

## 核心特性

- **高性能** - 毫秒级响应
- **易用性** - 零学习曲线
- **可扩展** - 灵活的插件系统
```

### 步骤 2: 生成 HTML

HTML 输出用于在线展示，包含完整的 GSAP 动画效果。

1. AI 读取 Markdown 内容
2. 智能分析并选择模板
3. 生成 HTML 代码到 `src/index.html`
4. 运行构建命令：

```bash
npm run build
```

输出：`dist/index.html` - 单个自包含文件，可离线工作

### 步骤 3: 生成 PPTX

PPTX 输出用于 PowerPoint 编辑和演示。

```bash
npm run build:pptx
```

或同时生成 HTML 和 PPTX：

```bash
npm run build:all
```

输出：`dist/presentation.pptx`

## 输出对比（HTML vs PPTX）

| 特性 | HTML | PPTX |
|-----|------|------|
| **用途** | 在线展示、网页嵌入 | 离线编辑、会议演示 |
| **动画** | GSAP 流畅动画 | PowerPoint 基础动画 |
| **文件** | 单个 HTML 文件 | PowerPoint 文件 |
| **兼容性** | 任何浏览器 | PowerPoint 2016+ |
| **文件大小** | 可能较大（图片嵌入） | 较小 |
| **可编辑性** | 需要修改代码 | 直接编辑 |
| **视觉效果** | 最佳 | 良好 |

**推荐使用场景**:
- **HTML**: 网站展示、在线会议、分享链接
- **PPTX**: 线下会议、客户演示、需要修改内容

## 核心布局模板详解

### 1. 封面页（固定）

**布局**：
- Logo: 左上角，50px（之前为60px，已优化）
- Slogan: 右上角，40px（之前为60px，已优化）
- 背景图: 全屏，opacity 0.5
- 主标题: 楷体优先（"楷体", "KaiTi", "Ma Shan Zheng", "ZCOOL XiaoWei", serif），4rem，加粗，黑色，左对齐，左缩进10%
- 副标题: 楷体优先，1.8rem，常规，黑色
- 日期: 楷体，1.5rem，黑色

**⚠️ 不可更改**，严格遵循固定规范。

**Markdown格式**：
```markdown
# 主标题
副标题
2025年2月
```

### 2. 左右分栏页

**布局**：
```
┌──────┬────────────────────┐
│      │  [模块1标题]       │
│ 图片  │  • 要点1          │
│ 或    │  • 要点2          │
│ 色块  ├────────────────────┤
│      │  [模块2标题]       │
│ 背景  │  • 要点1          │
│ 介绍  │  • 要点2          │
└──────┴────────────────────┘
```

**适用场景**：
- 项目介绍（左：项目背景图，右：项目内容）
- 公司介绍（左：公司照片，右：核心业务）
- 对比内容（左：方案A，右：方案B）

**Markdown格式**：
```markdown
## 项目介绍

![背景图](./assets/project.png)

### 项目背景
- 背景1
- 背景2

### 项目目标
- 目标1
- 目标2
```

### 3. 三栏并列页

**布局**：
```
┌─────────┬─────────┬─────────┐
│ [标题1] │ [标题2] │ [标题3] │
 ├─────────┼─────────┼─────────┤
 │ • 要点1 │ • 要点1 │ • 要点1 │
 │ • 要点2 │ • 要点2 │ • 要点2 │
 │ • 要点3 │ • 要点3 │ • 要点3 │
 └─────────┴─────────┴─────────┘
```

**适用场景**：
- 风险预案（三个风险类别）
- 工作成果（三个成果模块）
- 多维度对比（三个对比维度）
- 统计数据（三个关键指标）
- 团队介绍（三位成员）

**Markdown格式**：
```markdown
## 风险预案

### 风险1：技术风险
- 应对措施1
- 应对措施2

### 风险2：人员风险
- 应对措施1
- 应对措施2

### 风险3：进度风险
- 应对措施1
- 应对措施2
```

### 4. 中心辐射页

**布局**：
```
        [子模块1]
           ↗
[子模块5] ● → [子模块2]
           ↘
    [子模块4] [子模块3]
```

**适用场景**：
- 工作重点（中心：年度目标，周围：5大重点）
- 核心能力（中心：核心价值，周围：能力项）
- 战略规划（中心：总目标，周围：分目标）

**Markdown格式**：
```markdown
## 年度工作重点

**核心目标**：实现业务增长

- 重点工作1
- 重点工作2
- 重点工作3
- 重点工作4
- 重点工作5
```

### 5. 横向流程页

**布局**：
```
┌────┐    ┌────┐    ┌────┐    ┌────┐
│ 01 │ →  │ 02 │ →  │ 03 │ →  │ 04 │
├────┤    ├────┤    ├────┤    ├────┤
│标题│    │标题│    │标题│    │标题│
│描述│    │描述│    │描述│    │描述│
└────┘    └────┘    └────┘    └────┘
```

**适用场景**：
- 项目进展（4个阶段）
- 工作流程（5个步骤）
- 时间线（6个里程碑）
- 闭环流程（循环箭头）

**Markdown格式**：
```markdown
## 项目进展

1. **阶段1** - 需求分析
2. **阶段2** - 方案设计
3. **阶段3** - 开发实施
```

### 6. 数据总结页

**布局**：

**适用场景**：
- 成果汇报（卡片：成果详情，底部：关键数据）
- 年度总结（卡片：工作亮点，底部：业绩指标）
- 项目总结（卡片：项目内容，底部：完成情况）

**Markdown格式**：
```markdown

### 亮点1
- 要点1
- 要点2

- 要点2
```

## 封面页设计规范

**⚠️ 重要：封面页设计必须严格遵循以下固定模板要求，不得使用其他任何设计建议或变体。**

所有演示文稿的封面页必须使用以下固定设计，这是强制要求，不可更改：

### 固定元素

1. **Logo** (`./assets/logo.png`)
   - 位置：左上角
   - 高度：60px
   - Padding: 3.5% 5% 0 5%

2. **Slogan** (`./assets/slogon.png`)
   - 位置：右上角
   - 高度：60px
   - 与 Logo 同行

3. **背景图片** (`./assets/fm-background.png`)
   - 全屏覆盖
   - Opacity: 0.5
   - Z-index: 0

4. **主标题**
   - 字体：楷体
   - 字号：4rem (约48pt)
   - 字重：加粗
   - 颜色：黑色
   - 对齐：左对齐
   - Padding-left: 10%

5. **副标题**
   - 字体：楷体
   - 字号：1.8rem (约22pt)
   - 字重：常规
   - 颜色：黑色
   - 对齐：左对齐
   - Padding-left: 10%

6. **日期**
   - 字体：楷体
   - 字号：1.5rem (约18pt)
   - 颜色：黑色
   - 对齐：左对齐
   - 与副标题底部间距：30px

### 主内容区 Padding

- 上：12%
- 右：5%
- 下：8%
- 左：10%

**注意：`references/business-ppt-design-guide.md` 文件中不包含封面设计建议，因为封面必须严格遵循上述固定模板。请勿参考其他来源的封面设计建议。**

|---------|---------|-----|------|
| **中信红 (Primary)** | `#D20A10` | rgb(210, 10, 16) | 强调色、标题、重要元素 |
| **标准灰五 (Gray 5)** | `#575757` | rgb(87, 87, 87) | 深色文字、重要内容 |
| **标准灰四 (Gray 4)** | `#898989` | rgb(137, 137, 137) | 次要文字、说明文字 |

## 内容生成规则

### 1. 内容完整性

- **必须包含所有用户提供的内容** - 不得省略或简化
- **保留所有细节** - 如果用户提供 5 个要点，包含全部 5 个
- **不压缩或总结** - 保持提供的完整内容

### 2. 智能拆分

当内容过长时，自动拆分为多张幻灯片：

- **三栏并列**: 最多 3 个模块，超过则拆分
- **横向流程**: 最多 6 步，超过则拆分
- **列表内容**: 最多 8 项，超过则拆分
- **数据总结**: 卡片最多 4 个，数据最多 6 个

**16:9 边界限制（重要）**：

为确保内容不超出 16:9 比例的页面边界，必须严格遵守以下规则：

1. **页面内边距**: 使用 2.5vw（不是 3vw），为内容留出更多空间
2. **统计卡片紧凑化**:
   - 使用 `stat-card-mini` 类（不是 `stat-card`）
   - 图标大小: 2rem（不是 3rem）
   - 数据大小: 2rem（不是 3.5rem）
   - 内边距: var(--spacing-md)（不是 var(--spacing-xl)）
3. **字体大小控制**:
   - 正文列表: 0.9rem（不是 1rem）
   - 小标题: 0.95rem（不是 1rem）
4. **间距压缩**:
   - 卡片间距: var(--spacing-md) 或 var(--spacing-lg)
   - 列表项间距: var(--spacing-sm)（0.6rem）
5. **避免垂直堆叠过多元素**:
   - 单页最多 2-3 个主要区块
   - 超过则拆分为多页
   - 双栏布局优先于单栏堆叠
6. **大卡片优化**:
   - 统计卡片在双栏布局中应使用紧凑版
   - 避免在内容密集页面使用大型统计卡片
   - 优先使用小型标签或数字展示

### 3. 视觉风格多样化

**为避免页面单调，必须在同一演示文稿中使用多种卡片风格：**

#### 四种核心卡片样式

1. **经典左边框样式** (content-card)
   - 左侧4px红色边框
   - 白色背景
   - 适用于：常规内容、重点强调

2. **顶部渐变条样式** (content-card-style2)
   - 顶部4px红色边框
   - 白色背景
   - 适用于：次要内容、并列模块

3. **渐变背景样式** (content-card-style3)
   - 淡红色渐变背景 (rgba(210, 10, 16, 0.05) → white)
   - 2px红色半透明边框
   - 适用于：标杆案例、重要成果

4. **圆点装饰样式** (content-card-style4)
   - 左侧圆点装饰（16px红色渐变圆点）
   - 白色背景
   - 适用于：未来规划、创新内容

#### 风格分配规则

- **同一页面内避免使用相同样式超过2次**
- **相邻页面使用不同的样式组合**
- **重要程度高的内容优先使用style3（渐变背景）**
- **常规内容混合使用style1和style2**
- **创新、未来类内容使用style4（圆点装饰）**

#### 示例分配策略

```
第3页（4个卡片）: style1, style2, style3, style4
第4页（1个卡片）: style1
第5页（2个卡片）: style1, style2
第6页（3个卡片）: style1, style2, style3
第7页（2个卡片）: style1, style2
第8页（4个卡片）: style1, style2, style3, style4
```

### 4. 图片处理

- 使用 `./assets/` 路径格式
- Vite 构建时自动转换为 Base64 嵌入
- 支持远程 URL 和本地文件
- 推荐分辨率：≥1920×1080

## 最佳实践

### 1. 内容组织

- **每页一个主题**: 避免信息过载
- **控制要点数量**: 3-6 个最佳
- **使用简洁语言**: 避免长段落
- **突出关键信息**: 使用加粗或颜色

### 2. 模板选择

- 让系统自动匹配（推荐）
- 根据内容特征选择合适模板
- 同类型内容使用相同模板
- 保持视觉一致性

### 3. 动画使用

- HTML 版本包含流畅的 GSAP 动画
- 每页动画不超过 3-4 个
- 动画时长：0.3-0.8 秒
- 避免过度使用动画

### 4. 图片质量

- 使用高质量图片（≥1920×1080）
- 保持图片风格一致
- 适当压缩以减小文件大小
- 使用专业、商务的图片

## 常见问题

### Q: 如何指定使用特定模板？

A: Markdown 格式中，系统会根据内容自动选择。可通过内容结构暗示模板类型（如3个并列主题会匹配三栏并列页）。

### Q: HTML 和 PPTX 的视觉差异大吗？

A: 由于使用共享的设计令牌系统，两者在配色、字体、布局上保持一致。主要差异在于动画效果（HTML 使用 GSAP，PPTX 使用 PowerPoint 内置动画）。

### Q: 可以自定义配色方案吗？

A: 当前版本使用固定的中信配色方案。如需自定义，可以修改 `src/lib/design-tokens.js` 文件中的颜色值。

### Q: 支持哪些图片格式？

A: 支持 PNG、JPG、JPEG、GIF、SVG、WebP 格式。推荐使用 PNG 或 JPG。

### Q: 生成的文件可以在没有网络的环境使用吗？

A: HTML 文件是完全自包含的，所有资源（CSS、JavaScript、图片）都嵌入在单个文件中，可以离线使用。PPTX 文件也完全离线工作。

### Q: 如何处理过长的内容？

A: 系统会自动检测内容长度，超过模板限制时会智能拆分为多张幻灯片，确保所有内容都被包含。

## 技术架构

### 核心模块

- **markdown-parser.js**: 解析 Markdown 和纯文本输入
- **content-analyzer.js**: 分析内容特征，智能选择模板
- **template-mapper.js**: 将内容映射到模板数据结构
- **presentation-builder.js**: 主构建流程编排
- **html-generator.js**: 生成 HTML 代码
- **pptx-exporter.js**: 生成 PPTX 文件
- **design-tokens.js**: 共享设计令牌（颜色、字体、间距）
- **image-handler.js**: 图片处理和 Base64 转换
